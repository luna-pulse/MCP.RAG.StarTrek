# Инструкция: скачивание статей с сайта, перевод на русский и разметка на чанки `####`

Документ описывает 429 текстовых файлов на русском языке в папке `SourceFiles/Races`, размеченных разделителями `####` для последующего чанкинга в RAG.

Инструкция рассчитана на выполнение агентом в другом окне на другом сайте. Конкретные URL и имена
подставляются под новый источник; принципы и формат результата остаются теми же.

---

## 1. Требуемый результат

- Папка с текстовыми файлами: по одному файлу на сущность (расу, персонажа, статью).
- Имя файла — на русском языке, `<Русское название>.txt`, кодировка UTF-8 **без BOM**.
- Содержимое файла — перевод основного текста статьи на русский, разбитый на смысловые блоки.
- Каждый блок начинается со строки `####`, за ней строка заголовка блока с двоеточием, затем текст блока.

### Формат файла

```
# <Русское название>
Оригинальное название: <Original title>

####
Общие сведения:
<вводные абзацы статьи>

####
История:
<абзацы раздела>

####
История — Зеркальная вселенная:
<абзацы подраздела; родительский и дочерний заголовки через « — »>

####
Физиология (продолжение 2):
<если раздел длинный — следующая часть с тем же заголовком и пометкой «(продолжение N)»>

####
Заболевания:
- синдром Па'нар
- туванский синдром
```

### Правила разметки `####` (важно)

Хороший пример — один блок на смысловую единицу (раздел), внутри блока обычный текст и списки:

```
####
Заболевания:
- синдром
- болезнь 1
- болезнь 2
```

Плохой пример — решётки у каждого заголовка или у каждого пункта списка, решётки слитно с текстом:

```
#### Заболевания
####синдром
####  болезнь 1
```

Конкретно:
- `####` всегда стоит на отдельной строке, без текста после решёток.
- Следующая строка — заголовок блока, заканчивается двоеточием (`История:`).
- Пункты списков оформляются как `- пункт`, без решёток.
- Пустых блоков (заголовок без текста) быть не должно.
- Блоки разделяются одной пустой строкой.
- Между блоками не должно быть текста вне блоков (кроме шапки файла — первых двух строк).

## 2. Общая схема пайплайна

1. **Сбор списка ссылок** со стартовой страницы (каталог/оглавление).
2. **Скачивание основного текста** каждой целевой страницы (с учётом редиректов).
3. **Очистка**: удаление служебных разделов, сносок, навигационного мусора.
4. **Защита от перевода** того, что переводить нельзя (ссылки на серии, коды, названия в скобках) — замена на плейсхолдеры.
5. **Перевод** абзацев на русский батчами, с кэшированием на диске.
6. **Восстановление** плейсхолдеров.
7. **Сборка файла**: шапка + блоки `####` по разделам, разбиение длинных разделов, восстановление маркеров списков.
8. **Валидация** всего набора файлов и исправление найденных дефектов.
9. **Очистка репозитория** от временных файлов (сырьё и кэш — за пределы репозитория).

Все шаги автоматизируются одним скриптом с кэшем, чтобы пересборка после правки формата не требовала повторного
скачивания и перевода. На Windows без Python/Node использовался PowerShell 5.1 + `curl.exe` + `System.Net.Http.HttpClient`.

## 3. Шаг 1 — список ссылок

### Если сайт на MediaWiki (Fandom, Wikipedia и т.п.)

Не парсить HTML. Использовать API — список ссылок со страницы:

```
https://<host>/api.php?action=query&titles=<Page_Title>&prop=links&plnamespace=0&pllimit=500&format=json
```

- `plnamespace=0` — только статьи (без категорий, файлов, шаблонов).
- Если в ответе есть `continue.plcontinue`, повторить запрос с этим параметром.
- Из полученного списка **вручную исключить служебные ссылки**, которые есть на странице, но не являются целевыми
  сущностями (в примере: «Alpha Quadrant», «Beta Quadrant», «Species»).

### Если сайт обычный HTML

Скачать страницу, извлечь ссылки из нужного блока (`<ul>` списка/таблицы), нормализовать в абсолютные URL,
убрать дубликаты и якоря `#...`.

### Проверка объёма до начала работы

Запросить размеры страниц (`prop=info` → `length`, батчами по 40–50 заголовков) и посмотреть на распределение.
Это нужно, чтобы понять, сколько текста предстоит переводить, и заметить аномалии (например, ссылка ведёт на
огромную сводную страницу-список, а не на отдельную статью).

## 4. Шаг 2 — скачивание основного текста

### MediaWiki: TextExtracts (чистый текст с заголовками разделов)

```
https://<host>/api.php?action=query&prop=extracts&explaintext=1&exsectionformat=wiki&redirects=1&titles=<Title>&format=json
```

- Один запрос — одна страница (полный текст отдаётся только для одной страницы за раз).
- `exsectionformat=wiki` даёт заголовки вида `== История ==`, `=== Подраздел ===` — по ним и строятся блоки.
- `redirects=1` — следовать редиректам; в ответе `query.redirects[].to` показывает фактическую страницу.
  Сохранить и исходное название, и фактическое.
- Инфобоксы и таблицы в extract не попадают (это нормально — нужен основной текст).
- Списки приходят как отдельные строки **без маркеров** — маркеры восстанавливаются эвристикой (см. шаг 7).
- Пауза между запросами 250–300 мс, User-Agent вида `ProjectName/1.0 (educational local corpus)`, повтор при ошибке.

Сохранять каждый ответ в отдельный файл `_raw/<safe_title>.json` (символы `\ / : * ? " < > |` в имени заменить на `_`).
Пропускать уже скачанные файлы, чтобы скрипт можно было перезапускать.

### Обычный HTML

Скачать страницу, взять контейнер основного содержимого (например, `article`, `#content`, `.mw-parser-output`),
удалить `nav`, `aside`, `footer`, скрипты, инфобоксы, галереи, блоки «Читайте также». Заголовки `h2/h3/h4`
перевести в `== ==`/`=== ===`/`==== ====`, абзацы `p` и пункты `li` — в отдельные строки. Дальше обработка общая.

### Особые случаи, которые встретились и как они решались

- **Редирект на уже существующую в списке сущность** (Kaitlen → Kobliad): вторую копию не создавать, вести список
  исключений `$skipTitles`.
- **Редирект на сводную страницу-список** (Tyken's Rift being → «Unnamed humanoids (24th century)»): брать только
  раздел с нужным заголовком, вести словарь `$sectionOnly = @{ "<title>" = "<Section heading>" }`.
- **Редирект на страницу другой природы** (ссылка «X's species» ведёт на статью о персонаже X): переводить как есть,
  но в шапке указывать оригинальное название ссылки, чтобы было видно, откуда файл.

## 5. Шаг 3 — очистка

Разбор текста построчно:

- Заголовок: регулярка `^\s*(={2,6})\s*(.+?)\s*\1\s*$` → уровень = число `=`, название = группа 2.
- Разделы, которые **удаляются вместе со всеми подразделами** :
  `Appendices, Background information, Background, Apocrypha, External link(s), Appearances, References,
  Further reading, Sources, Notes, Gallery, Images, Production, Reception, Related links, Links`.
  Реализация: при встрече удаляемого заголовка уровня L пропускать всё до следующего заголовка уровня ≤ L.
- Оставляются содержательные разделы, в том числе короткие («См. также», «Отдельные представители»).
- Из строк удалить: маркеры вида `(β)` (ссылки на Memory Beta), сноски `[1]`, `[2]`, лишние пробелы.
- Пустые строки — границы абзацев. Каждая непустая строка — отдельный абзац/пункт списка.
- Строка, состоящая только из ссылки на серию (`(TNG: "...")`), приклеивается к предыдущему абзацу.

Для каждого раздела сохранять **путь заголовков** (`@("История", "Зеркальная вселенная")`), чтобы потом собрать
заголовок блока `История — Зеркальная вселенная:`. Текст до первого заголовка — раздел с путём пустым, в файле он
получает заголовок `Общие сведения:`.

## 6. Шаг 4 — защита от перевода (плейсхолдеры)

Машинный переводчик портит ссылки на источники: `(ENT: "Broken Bow")` превращается в `(ЛОР: сломан`.
Поэтому перед переводом все такие фрагменты заменяются на ASCII-плейсхолдеры, а после — возвращаются.

```
\((?:TOS|TAS|TNG|DS9|VOY|ENT|DIS|PIC|LD|PRO|SNW|ST|VST|SFA|Star Trek|citation)(?:[^()]|\([^()]*\))*\)
```

Правила:
- Плейсхолдер только из латиницы и цифр, без пробелов: `XQCITE0XQ`, `XQCITE1XQ`, … (нумерация сквозная по странице,
  оригиналы складываются в массив по индексу). Такой токен переводчик оставляет как есть.
- **Не использовать кириллицу в плейсхолдерах и в отправляемом тексте** — при передаче через `curl --data-urlencode`
  из PowerShell кириллица ломается (`Ð¥Ð¾Ñ€Ñ‚Ð°`).
- При восстановлении искать плейсхолдер толерантно: `(?i)XQ\s*CITE\s*(\d+)\s*XQ` (переводчик может вставить пробелы
  или изменить регистр). Если какой-то плейсхолдер абзаца всё же пропал — дописать его оригинал в конец абзаца,
  чтобы ссылка на источник не потерялась.
- После восстановления убрать пробел перед знаками препинания и двойные пробелы.

Для другого сайта определить свой список того, что нельзя переводить (коды, артикулы, формулы, названия в оригинале),
и защищать их тем же способом.

## 7. Шаг 5–7 — перевод, восстановление, сборка

### Перевод

Рабочий бесплатный эндпоинт (без ключа), который не блокировал запросы при умеренной нагрузке:

```
POST https://clients5.google.com/translate_a/t?client=dict-chrome-ex&sl=en&tl=ru
Content-Type: application/x-www-form-urlencoded
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... Chrome/128.0.0.0 Safari/537.36
Body: q=<абзац 1>&q=<абзац 2>&...   (каждое значение через [uri]::EscapeDataString)
Ответ: JSON-массив строк в том же порядке: ["перевод 1","перевод 2",...]
```

Что не сработало: `translate.googleapis.com/translate_a/single` (быстро отдаёт «Sorry... automated queries»),
`lingva.ml` (возвращает исходный текст), `libretranslate.com` (требует ключ), MyMemory (качество низкое, лимиты).

Параметры батчей, при которых всё прошло без единой ошибки: до 25 абзацев и до 7000 символов на запрос,
пауза 350 мс между запросами, при ошибке — экспоненциальная задержка (3, 6, 12 … с) и 6 попыток,
при неудаче батча — перевод его элементов по одному. Абзацы длиннее 12 000 символов делить по предложениям.
Общая скорость: ~430 страниц, ~2 МБ исходного текста — около 10 минут.

Обязательно проверять, что число строк в ответе равно числу отправленных абзацев.

### Кэш

На каждую страницу — JSON `_tr_cache/<safe_title>.json` вида `{ "<исходный абзац с плейсхолдерами>": "<перевод>" }`.
Перед переводом брать из кэша всё, что уже есть. Благодаря этому любая правка формата (заголовки, размер блоков,
шапка) пересобирает весь набор за ~20 секунд без обращений к переводчику.

При загрузке кэша отбрасывать подозрительные записи: перевод короче 30 % длины оригинала при оригинале длиннее
8 символов (так ловятся испорченные значения).

### Заголовки разделов

Частые заголовки переводить по словарю, чтобы они были единообразны (`History → История`, `Physiology → Физиология`,
`Society and culture → Общество и культура`, `Individuals → Отдельные представители`, `See also → См. также`,
`Mirror universe → Зеркальная вселенная`, `Alternate reality → Альтернативная реальность` и т.д.),
остальные — через тот же переводчик, с удалением точки в конце.

### Названия сущностей (имена файлов)

Машинный перевод названий ненадёжен (`Andorian → Андорианец`, `892-IV native → 892-IV родной`).
Словарь `Оригинал → Русское название` составляется **вручную** агентом один раз в TSV (`_names_ru.tsv`), в форме
множественного числа для рас (`Клингоны`, `Баджорцы`), с шаблонами для типовых случаев:
`X native → Жители X`, `X's species → Раса X`, `X (species) → X`. Проверить, что русские названия уникальны и
не содержат запрещённых в именах файлов символов.

### Восстановление списков

TextExtracts теряет маркеры списков. Эвристика: строка считается пунктом списка, если она короче ~90 символов и не
заканчивается на `. ! ? … » " ) ]`. Такие строки выводятся как `- пункт` (точку в конце убрать). Полные
предложения остаются абзацами.

### Разбиение длинных разделов

Абзацы раздела упаковываются в блок, пока его длина не превышает ~1800 символов; соседние пункты списка не
разрывать (допускается до ~3000 символов). Первый блок получает заголовок `Раздел:`, последующие —
`Раздел (продолжение 2):`, `(продолжение 3):` и т.д. Разделы без текста (только контейнеры подразделов) блоков не создают.

### Шапка файла

```
# <Русское название>
Оригинальное название: <Original title>
<пустая строка>
```

Строка «Источник: <URL>» изначально добавлялась, затем по требованию удалена из всех файлов — лучше сразу
уточнить у заказчика, нужна ли она.

## 8. Шаг 8 — валидация набора

Проверить по всем файлам и вывести список нарушений:

- число файлов совпадает с числом целевых ссылок минус исключения;
- нет остатков плейсхолдеров: `(?i)XQ\s*CITE`;
- в каждом файле есть хотя бы один блок: строка `^####$`;
- нет `####` слитно с текстом (`####\S`);
- нет пустых блоков: `^####\n[^\n]+\n(\n|$)`;
- в теле (после шапки) кириллических букв больше, чем латинских — иначе абзац не переведён или обрезан;
- ручной просмотр 3–5 файлов разного размера (маленький, средний, самый большой) и одного «особого случая».

Именно такая проверка выявила дефект: 8 абзацев превратились в одну букву (см. ниже), после чего испорченные
записи кэша были отброшены и всё пересобрано.

## 9. Технические ловушки (Windows PowerShell 5.1)

- **Кириллица в `.ps1`**: Windows PowerShell читает файл без BOM как ANSI → ошибки парсинга. Сохранять скрипт
  в UTF-8 **с BOM** (`New-Object Text.UTF8Encoding($true)`), а выходные `.txt` — в UTF-8 **без BOM**.
- **Разворачивание массивов**: функция, возвращающая массив из одного элемента, вернёт строку; `$res[$i]` на строке
  даёт один символ. Всегда оборачивать: `$res = @(Invoke-Batch $batch)` и проверять `$res.Count -eq $batch.Count`.
- **Scriptblock-замыкания** (`& $emit`) не меняют внешние переменные — счётчики `part`/`blocks` не растут.
  Собирать чанки в массив и выводить обычным циклом.
- `Invoke-RestMethod`/`Invoke-WebRequest` в 5.1 может падать с `Invalid URI`/`NullReference`; надёжнее
  `curl.exe` для GET и `System.Net.Http.HttpClient` + `StringContent` для POST.
- Параметр-массив при `powershell -File script.ps1 -Only A,B` приходит одной строкой `"A,B"` — разбивать по запятой внутри.
- `FormUrlEncodedContent` из PowerShell не принимает список пар — формировать тело вручную.
- Вывод кириллицы в консоли может выглядеть как `????` — это проблема консоли, не файлов; проверять содержимое
  чтением файла как UTF-8.

## 10. Что сохранить и что удалить

В репозитории остаются только итоговые `.txt`. Всё остальное вынести за пределы репозитория (но не удалять,
чтобы можно было пересобрать): скрипт сборки, словарь имён, сырые выгрузки `_raw/`, кэш переводов `_tr_cache/`,
отчёт сборки. Для текущего проекта это лежит в `%LOCALAPPDATA%\Temp\startrek_races_tools`.

## 11. Краткий чек-лист для агента

1. Получить список ссылок (API, если есть), исключить служебные, оценить объём.
2. Скачать основной текст каждой страницы в `_raw/`, с редиректами и повторами; зафиксировать особые случаи.
3. Составить вручную словарь русских названий → имена файлов.
4. Определить удаляемые разделы и регулярку защиты непереводимых фрагментов на 3–5 примерах.
5. Написать один скрипт: очистка → плейсхолдеры → перевод батчами с кэшем → восстановление → сборка блоков `####`.
6. Прогнать на 2–3 страницах (маленькая, большая, особая), проверить глазами, затем на всём наборе в фоне с логом.
7. Запустить валидацию по п. 8; исправить дефекты; пересобрать из кэша.
8. Вынести временные файлы из репозитория; отчитаться: сколько файлов, сколько блоков, какие особые случаи.
