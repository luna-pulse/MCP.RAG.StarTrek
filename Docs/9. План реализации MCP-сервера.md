# План реализации MCP-сервера

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTTP-сервер MCP на .NET 10 отдаёт чанки корпуса Star Trek тремя инструментами: `search_bm25`, `search_semantic` и `search_hybrid`, не индексируя корпус и не сочиняя ответ.

**Architecture:** Новый проект `src/StarTrek.Mcp` — хост ASP.NET Core со Streamable HTTP. Он ссылается на `StarTrek.Indexer` и вызывает уже существующие `Bm25IndexHolder`, `ChromaHttpClient`, ленивый `IQueryEmbeddingGenerator` и `HybridSearchService`. Общие записи ответа (`SearchChunk`, `ChunkSearchResponse`) и два тонких поиска (слова и смысл) живут в `StarTrek.Indexer.Search`, чтобы в MCP не появился второй набор имён и вторая реализация RRF. `AddStarTrekIndexer` не подключается: команды `analyze`, `chunk` и `embed` и немедленная загрузка ONNX серверу не нужны. Журнал — `ILogger` и два файловых приёмника GELF, без канала логирования MCP и без живого Graylog.

**Tech Stack:** C# / `net10.0`, SDK `10.0.401` (`rollForward: latestPatch`). Пакеты `ModelContextProtocol` и `ModelContextProtocol.AspNetCore` ровно `2.2.0` (стабильная линия 2.x; не `0.x` и не `1.x`). Транспорт — `WithHttpTransport` + `HttpServerSessionMode.Stateless` + `MapMcp`. Журнал — `NLog` `4.7.15`, `NLog.Extensions.Logging` `1.7.5`, `NLog.GelfLayout` `1.5.0` (раскладка `${gelf}` в `FileTarget`; NLog 5/6 не ставить: сборка GelfLayout 1.5.0 — под NLog 4.7). Скриншоты прогонов — `SixLabors.ImageSharp` `3.1.12`. Тесты — xUnit, как в `StarTrek.Indexer.Tests`.

Справочники `references/packages.md`, `references/transport-http.md`, `references/tool-primitive.md` и `references/testing.md` рядом со скилом в репозитории отсутствуют. Сигнатуры ниже взяты из кардинальных правил скила `dotnet-mcp-builder`, из Context7 `/modelcontextprotocol/csharp-sdk` и из исходников пакета 2.2.0 (`McpServerToolAttribute.Name`, `McpException(string)`, `McpException(string, Exception)`, `UseStructuredContent`, `ReadOnly`). Метод, которого нет в этом списке, не выдумывать: сверить с https://csharp.sdk.modelcontextprotocol.io/api/ModelContextProtocol.html и с Context7 до кода.

**Spec:** `Docs/8. Спецификация MCP-сервера.md`

## Global Constraints

- Рантайм — `net10.0`. Версия SDK — `10.0.401` с `rollForward: latestPatch`, как в `global.json`.
- Пакеты MCP — стабильная линия 2.x, номера зафиксированы: `ModelContextProtocol` `2.2.0` и `ModelContextProtocol.AspNetCore` `2.2.0`. Превью `0.x` и линия `1.x` не используются.
- Транспорт — Streamable HTTP. `WithStdioServerTransport` не вызывается. `EnableLegacySse` не включается. `Stateless = false` не задаётся. Режим: `options.SessionMode = HttpServerSessionMode.Stateless`.
- Промптов, ресурсов, completions, elicitation, MCP Apps и Tasks нет. Корни, sampling и логирование по каналу MCP не проектируются. Только три инструмента.
- Python, FastMCP, LangChain, LangGraph и Ollama не добавляются. Платный API эмбеддингов не вызывается. `AddKernel` и `AddLocalE5EmbeddingGenerator` из регистрации сервера не вызываются.
- Идентификаторы в коде — на английском. Описания инструментов, тексты ошибок инструментов, сообщения журнала для человека и документы в `Docs/` — на русском.
- Новая папка — CamelCase с заглавной буквы. Тесты — `Tests/StarTrek.Mcp.Tests`. Журнал — `Data/Logs`.
- Пороги, адреса и пути журнала — в `appsettings.json` и в переменных `STARTREK_`. В коде те же числа и пути не дублируются вторым источником. Секция `Indexer` читается из `src/StarTrek.Indexer/appsettings.json`; второй копии порогов в проекте MCP нет.
- BM25: `K1 = 1.5`, `B = 0.75`. Коллекция ChromaDB — `startrek`. Размер вектора — 384 (`OnnxE5EmbeddingGenerator.Dimensions`). RRF `k` — `Indexer:Search:RrfK` (в файле индексатора сейчас 60). `VectorTopN` и `Bm25TopN` в файле — 20. `ResultCount` — 10.
- Префикс запроса `query: ` добавляет только `IQueryEmbeddingGenerator.GenerateQueryAsync`. Инструмент и `SemanticSearchService` префикс не приписывают. Префикс `passage: ` в вызов запроса не подставляется.
- Текст чанка в ответе — как в коллекции: сервер не добавляет `passage: ` и не вставляет `#`.
- MCP не пишет в ChromaDB, `Data/bm25`, `Data/staging`, `ChromaDB/` и `SourceFiles/`. Единственная запись процесса сервера на диск — файлы журнала по путям `Mcp:Logging`. Папку `ChromaDB` процесс не открывает. Команды индексатора сервер не вызывает. `embed` этот план не запускает.
- `model.onnx` в git и в образ Docker не кладётся. Слушатель поднимается без `model.onnx`, без `tokenizer.json`, без `Data/bm25/corpus.json` и без ответа ChromaDB.
- `nullable` и неявные `using` включены. Пространство имён сервера — `StarTrek.Mcp`. Тесты — `StarTrek.Mcp.Tests`.
- Том `./ChromaDB:/data` не переименовывать. У сервиса `mcp` каталог `/data` не используется.
- Существующие тесты `StarTrek.Indexer.Tests` и команды индексатора не менять. `HybridSearchService` не переписывать: RRF остаётся внутри него.
- Коммит не делать, пока об этом отдельно не попросит человек.
