# Экранирование и длина ответов MCP

Ответ поиска раздут из-за двойной сериализации. SDK превращает объект модели в JSON-строку и кладёт её в `TextContentBlock.Text`. Наружный писатель записывает эту строку ещё раз. Клиент видит `text` как строку, внутри которой кириллица уже символами `\u043A`, а кавычки как `\"`.

Нужный ответ другой. В `content` поле `text` — JSON-объект с теми же полями модели (`query`, `chunks` и поля чанка). Русские буквы записаны как буквы. В теле, которое видит клиент, нет последовательностей `\uXXXX`. Длина этого объекта не больше порога, около 30000 символов.

## Что не меняем

Имена и набор полей `ChunkSearchResponse` и `SearchChunk` остаются: `query`, `chunks`, `id`, `text`, `bm25Score`, `distance`, `rrfScore`, `vectorRank`, `bm25Rank`, `sourceFile`, `title`, `originalTitle`, `entityType`, `sectionPath`, `position`, `chunkIndex`. Атрибуты `JsonPropertyName` и `JsonIgnore(WhenWritingNull)` не трогаем. Файлы этих типов лежат в индексаторе, их не открываем.

Три инструмента, `UseStructuredContent = true`, транспорт и пути журнала остаются. Сериализацию Chroma, BM25 и staging не трогаем.

Правим только проект `src/StarTrek.Mcp`. `src/StarTrek.Indexer`, `Tests` и остальные проекты солюшена не меняем.

## Почему SDK сам объект не запишет

Пакет `ModelContextProtocol` 2.2.0. `TextContentBlock.Text` имеет тип `string`. `ContentBlock.Converter.Write` вызывает `writer.WriteString("text", text)`. `WriteRawValue` в этом конвертере нет. `TextContentBlock` закрыт, конструктор `ContentBlock` чужой сборке недоступен, свой блок содержимого добавить нельзя.

`McpJsonUtilities.DefaultOptions` собирается в `CreateDefaultOptions` и там же вызывается `MakeReadOnly()`. Подставить в него `Encoder` нельзя. Байты клиенту пишет `McpSseEventWriterExtensions`: `new Utf8JsonWriter` со стандартным encoder (`JavaScriptEncoder.Default`) и `JsonSerializer.Serialize` по `McpJsonUtilities.JsonContext.Default.JsonRpcMessage`. Этот писатель наши options не принимает. Тело — SSE `text/event-stream`: строка `event: message` и строка `data:` с JSON-RPC.

`WithTools(JsonSerializerOptions)` меняет только JSON, который SDK затем кладёт в строку `Text` и в `structuredContent`. Возврат `CallToolResult` из инструмента всё равно проходит через `WriteString`. На проводе `text` остаётся строкой.

Схема MCP описывает `text` как строку, и клиент Cursor может отбросить блок. Требование плана другое: записать в `text` объект.

## Как пишем ответ

В `McpHost` перед `MapMcp` тело ответа буферизуется. Переписываем только ответ вызова инструмента. Остальные сообщения уходят как записал SDK.

В `result.content` у блока `"type": "text"` значение `text` — строка с JSON модели. Строку разбираем в объект и ставим объект на место строки. Обычная фраза ошибки остаётся строкой.

Тот же SSE пишем сами. JSON внутри `data:` пишет наш `Utf8JsonWriter` с `JsonWriterOptions.Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`. Поле `text` пишем через `WriteRawValue`: в писатель уходят байты объекта, собранные тем же encoder. На проводе получается `"text": { "query": "...", "chunks": [ ... ] }`, кириллица — буквами UTF-8.

Кавычка, обратный слэш и управляющие символы внутри строковых значений экранируются один раз (`\"`, `\\`, `\n`). Иначе JSON невалиден. Это не `\uXXXX`. Перевод строки внутри `chunks[].text` остаётся одним `\n`, потому что `text` блока уже не строка внутри строки.

`structuredContent` SDK по-прежнему собирает из того же уже урезанного объекта. Его запишет этот же писатель, буквами и без `\uXXXX`.

Один экземпляр `JsonSerializerOptions`: копия флагов `McpJsonUtilities.DefaultOptions`, на копии `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`. Им меряем длину и им собираем байты для `WriteRawValue`.

## Длина не больше 30000

Порог — `MaxResponseCharacters` в секции `Mcp`: `src/StarTrek.Mcp/appsettings.json` и `McpOptions`, рядом с `Path`, `Urls`, `Logging`. Значение 30000. Переменная `STARTREK_Mcp__MaxResponseCharacters` перекрывает файл тем же префиксом, что уже собирает `McpConfiguration`. В коде обрезки число 30000 не писать: читать `IOptions<McpOptions>`.

Считаем символы JSON объекта модели — того, что станет значением `text`. Если строка длиннее порога:

1. Убирать элементы `chunks` с конца, пока JSON не влезет. Порядок лучших попаданий сохраняется.
2. Если не влезает один чанк — укорачивать его `text` с конца и сериализовать снова.
3. Когда что-то урезали, в конец `text` последнего оставшегося чанка дописать короткую русскую пометку, что ответ обрезан по длине. Пометка входит в длину. Новых свойств у модели нет.

Обрезка — в `SearchTools.InvokeAsync`, до возврата, чтобы три метода не расходились.

## Где править

- `src/StarTrek.Mcp/McpHost.cs` — буфер SSE, разбор `data:`, `Utf8JsonWriter`, `WriteRawValue`. В журнал исходящего ответа писать уже переписанное тело.
- `src/StarTrek.Mcp/SearchTools.cs` — замер и обрезка в `InvokeAsync`.
- `src/StarTrek.Mcp/McpOptions.cs` и `src/StarTrek.Mcp/appsettings.json` — порог `MaxResponseCharacters`.

## Как проверить

Смотреть тело, которое middleware отдаёт клиенту. Оно же попадает в журнал исходящего ответа. У `content[0].text` объект с `query` и `chunks`, русские буквы читаются сразу, последовательностей `\u041A` и `\u0022` нет, кавычка в строке чанка записана как `\"`. Ответ длиннее порога урезается, в конце `text` последнего чанка есть пометка, имена полей прежние.
