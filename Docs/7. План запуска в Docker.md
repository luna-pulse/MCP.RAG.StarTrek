# План запуска индексатора в Docker

Консоль `StarTrek.Indexer` собирается и запускается в Docker. Этот файл — спецификация уже реализованного запуска, а не список будущих работ.

Проверка запуска — только команда `health-check`. Команды `analyze`, `chunk` и `embed` в проверке не запускаются, корпус в ChromaDB не пишется, папки `Data/`, `ChromaDB/` и `SourceFiles/` не меняются.

Имена образа и контейнеров — `startrek-indexer` и `startrek-chromadb`. В них нет `MCP` и `RAG`. Файл решения `MCP.RAG.StarTrek.sln` — это имя репозитория, не имя образа.

Локально, без контейнера индексатора: `dotnet run --project src/StarTrek.Indexer -- <команда>`. Для этого пути нужен SDK .NET 10 на хосте. Для Docker-пути SDK на хосте не нужен: он уже внутри образа.

## Файлы

Уже есть в корне и в проекте индексатора:

- `src/StarTrek.Indexer/Commands/CommandDispatcher.cs` — команда `health-check` и строка в справке.
- `Dockerfile` в корне — многостадийная сборка и публикация.
- `.dockerignore` в корне — контекст сборки без лишнего.
- `docker-compose.yml` — два сервиса: `chromadb` и `indexer`. Том Chroma остаётся `./ChromaDB:/data`: образ Chroma ждёт каталог `/data`.

`src/StarTrek.Indexer/appsettings.json` для локального запуска не меняется. Адрес Chroma в файле — `http://127.0.0.1:8000`, чтобы `dotnet run` на машине разработчика работал как раньше. Внутри Compose адрес задаётся переменной окружения.

Тесты для Docker-запуска не добавлялись и не запускаются.

## Команда health-check

Имя команды — `health-check` (строчные буквы, через дефис), в том же стиле, что `analyze`, `chunk`, `embed`.

Поведение:

- печатает в stdout одну короткую строку: `Индексатор отвечает: healthy.`;
- возвращает код выхода 0;
- не принимает параметров.

Ветка `health-check` в `CommandDispatcher` не вызывает `GetRequiredService` для `AnalyzeCommand`, `ChunkCommand`, `EmbedCommand`, `E5Tokenizer` и генератора ONNX. Эти сервисы регистрируются лениво и создаются только когда их команда реально выполняется. Иначе старт потребует `tokenizer.json` и `model.onnx`.

Неизвестная команда пишет ошибку и возвращает код 2. Пустой список аргументов печатает справку и возвращает 2. Команда `help` печатает ту же справку и возвращает 0. Справка перечисляет `health-check`.

`health-check` не открывает корпус, не читает `model.onnx` и не делает запросов к ChromaDB. `ValidateOnStart` проверяет только строки и числа настроек, а не наличие файлов корпуса.

Процесс ищет корень репозитория через `RepositoryPathResolver`: вверх от текущей папки и от `AppContext.BaseDirectory`, пока не найдётся `MCP.RAG.StarTrek.sln`. Рядом с программой находится `appsettings.json` (его кладёт `dotnet publish`, потому что в csproj стоит `CopyToOutputDirectory`).

## Образ

Базовые образы — glibc, не Alpine: проект ссылается на `Microsoft.ML.OnnxRuntime`, даже если `health-check` модель не грузит.

- сборка: `mcr.microsoft.com/dotnet/sdk:10.0`
- запуск: `mcr.microsoft.com/dotnet/runtime:10.0`

SDK .NET 10 входит в образ. На хосте для сборки и запуска контейнера он не нужен.

В стадии сборки копируются `global.json` (пин SDK `10.0.401`, `rollForward: latestPatch`), `MCP.RAG.StarTrek.sln`, файл `src/StarTrek.Indexer/StarTrek.Indexer.csproj` (для `dotnet restore`), затем каталог `src/StarTrek.Indexer`. Публикация: `dotnet publish` проекта индексатора в конфигурации Release. Тестовый проект в образ не входит.

В финальном образе раскладка такая:

```text
/opt/startrek/MCP.RAG.StarTrek.sln
/opt/startrek/app/StarTrek.Indexer.dll
/opt/startrek/app/appsettings.json
```

Рабочая папка — `/opt/startrek/app`. Файл решения лежит на уровень выше, поэтому `FindRepositoryRoot` его находит. `model.onnx` в образ не копируется. Для вывода кириллицы в контейнере задано `LANG=C.UTF-8`.

`ENTRYPOINT` — `dotnet StarTrek.Indexer.dll`. `CMD` — `health-check`. Аргумент `docker compose run … health-check` подменяет только `CMD` и не затирает запуск `dotnet`.

## Compose

Два сервиса.

Сервис `chromadb`:

- образ `chromadb/chroma:1.5.9`, контейнер `startrek-chromadb`;
- порты `8000:8000`;
- том `./ChromaDB:/data` — путь `/data` не переименовывать: его ждёт образ Chroma;
- `restart: unless-stopped`.

Сервис `indexer`:

- образ `startrek-indexer`, контейнер `startrek-indexer`;
- собирается из `Dockerfile` в корне;
- `depends_on: chromadb` — только порядок запуска, без обращения к API Chroma из `health-check`;
- переменная `STARTREK_Indexer__Chroma__Endpoint=http://chromadb:8000` (префикс `STARTREK_`, разделитель `__`);
- команда по умолчанию — `health-check`, поэтому `docker compose up` и `docker compose run` без аргумента не индексируют корпус;
- политики `restart` у индексатора нет: команда завершается и не должна крутиться заново.

Другие команды индексатора в контейнере:

```powershell
docker compose run --rm -T indexer <команда>
```

Это не проверка данного плана. Для проверки запуска используется только `health-check`.

## .dockerignore

Из контекста сборки исключаются:

- `**/bin/` и `**/obj/`;
- `.git`, `.vs`, `.vscode`, `.idea`;
- `Tests/` и `tests/` (тесты для образа не нужны);
- `Models/multilingual-e5-small/model.onnx`;
- `Data/`, `data/`, `ChromaDB/`, `SourceFiles/` — для компиляции и для `health-check` не нужны, в контекст их не кладём.

Это исключение из контекста сборки, а не удаление файлов на диске.

## Как проверить, ничего не индексируя

Собрать образ и запустить только `health-check`:

```powershell
docker compose build indexer
docker compose run --rm -T --no-deps indexer health-check
```

`--no-deps` не поднимает ChromaDB. Если порт 8000 уже занят существующим контейнером Chroma, данные не трогаем: не выполняем `docker compose down -v` и не очищаем `./ChromaDB`.

Ожидание: код выхода 0 и строка `Индексатор отвечает: healthy.` в stdout.

Не запускать `analyze`, `chunk`, `embed` — ни локально, ни в контейнере. Не вызывать поиск.
