## Corrective RAG: Semantic Kernel вместо LangGraph

Этот раздел добавлен при реализации инструмента `ask_question`.

Исходное ТЗ описывало граф на LangGraph и LangChain (Python) и локальную модель через Ollama. В репозитории к этому моменту уже был другой стек: C# / .NET 10, индексатор, ChromaDB, BM25 и три инструмента MCP. Оркестрацию с самого начала планировали на Microsoft Semantic Kernel, без Python. Поэтому тот же Corrective RAG собран здесь, а не переносом LangGraph.

Почему Semantic Kernel, а не LangGraph:

- Язык решения уже C#. Второй рантайм ради одного графа тащит за собой дубль поиска, который в `HybridSearchService` уже есть: BM25, вектор и RRF.
- Четыре шага — обычные функции ядра `KernelFunctionFactory.CreateFromPrompt`. Тексты лежат в `src/StarTrek.Mcp/Prompts`, порог и число повторов — в `appsettings.json`.
- Чат идёт в локальную Ollama пакетом `Microsoft.SemanticKernel.Connectors.Ollama` 1.81.0-alpha через `IChatClient` (внутри OllamaSharp). Платный API не вызывается. Эмбеддинги по-прежнему считает ONNX `intfloat/multilingual-e5-small`, не модель Ollama.
- Модель по умолчанию — `qwen2.5:3b`, как в примере ТЗ. Адрес и имя модели меняются конфигом.

Почему цикл в `CorrectiveRagService`, а не Process Framework Semantic Kernel. У графа одна развилка: релевантных чанков хватает — Generate, нет — Broaden и повтор, не больше двух раз. Process Framework разворачивает это в события и состояние процесса. Проверять «хватило сразу», «одно расширение», «два расширения и стоп» проще на прямом цикле с подменённой моделью. Сами Rewrite, Grade, Broaden и Generate остаются функциями ядра и в тестах вызываются через настоящий `Kernel` с подменённым чатом.

Если после двух расширений релевантных чанков нет, Generate не вызывается. Ответ фиксированный: «В базе знаний Star Trek об этом ничего не найдено.» Так модель не дописывает факт из своих весов. Если чанк есть, но порог так и не набран, ответ пишется по тем чанкам, которые Grade пометил.

Ошибки Ollama и ChromaDB наружу идут текстом инструмента MCP, слушатель не падает. Перед первым вызовом сервер читает `GET /api/tags`: нет соединения или нет модели в списке — отдельные русские сообщения.
